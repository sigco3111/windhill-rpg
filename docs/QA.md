총 75개 단언입니다. 같은 스크립트의 재실행은 중복 계산하지 않았습니다. 여정 계승 UI 검사의 첫 준비 저장은 순례길 완료 조건이 빠져 선택이 나타나지 않았습니다. 정상적인 진행 잠금이었으며, 검사 저장에 완료 조건을 명시한 뒤 다시 검사했습니다. 이 때문에 게임 코드를 바꾸지 않았습니다.

부츠 이동 검사의 첫 시도는 키를 뗀 뒤 시간과 위치를 따로 읽어 표본 시점이 어긋났습니다. 키를 누른 동안 같은 게임 관측 표본의 시간/위치를 함께 읽도록 검사 코드를 고쳤습니다. 게임 이동 코드는 바꾸지 않았습니다. 보정된 검사에서 2.03게임초 동안 이동7.41m, 계산7.40544m였습니다. 이는 준비한 통로의 이동 배율 검사이며 FPS나 자연 플레이 측정은 아닙니다.

## 화면 검사

320×700 가방/상세, 700×320 가방/상세/분해 경고를 실제 픽셀로 확인했습니다. 첫 가로 상세창은 버튼이 잘려 있어 본문 스크롤과 고정 버튼을 분리했습니다. 이후 본문의 일반 줄바꿈과 긴 토큰 감싸기를 명시했습니다. 700×320 본문은 가로440px에서 가로 넘침 없이 세로 스크롤로 마지막 줄까지 읽힙니다. README에 넣은 이미지도 실제 실행 화면입니다. 로컬에서 찍은 이미지에는 로컬 검사 화면임을 밝혔습니다.

## 보존과 제한

- 기존 `fan-wind` 후보는 별도로 보존했습니다. 이번 소스에 검사 전용 적 배치·준비 훅을 붙이지 않았습니다.
- `gear`의 숫자 등급 호환 기록을 유지하면서 `equipment`에 보유품/강화/장착/보상 기록을 저장합니다.
- 기존 장착품은 같은 등급/강화0으로 이전합니다. 완료한 장비 의뢰 보상은 최초 이전 때만 소급합니다.
- `7917931009658dd1cd68caff6a630ba66ff3f44c`로 소스를 게시했고 실제 배포 작업43767498780의 빌드·배포 성공을 확인했습니다. 기존 workflow는 변경하지 않았습니다.
- 실제 주소에서 새 index-DkuxHLi4.js 번들, 기사/장로/적 모델과 폰트/OFL의 정상 응답, 별도 검사 저장의 장비 UI13항목, 기본 그래픽 마을/새 보관함 실제 화면을 확인했습니다. 기본 그래픽 첫 로딩은 검사 환경에서2분 이상 걸렸으며 실제 휴대폰 측정은 아닙니다.
- 외부 원본으로 에셋을 새 다운로드한 뒤 로컬 빌드도 통과했습니다.
- 전체 첫 회차, 모든 다회차, 모든 보스·기술 조합, 장시간 모바일 성능, 실제 기기 소리, 장기 골드 수급 밸런스는 검증하지 못했습니다.
